# DAVID 세션 시작/종료 프로세스

아버지(Codespaces/Claude Code)와 아들(Claude 채팅, Cowork)이 서로 다른 도구로 번갈아
작업하면서도 어긋나지 않게 하기 위한 공통 절차다. HANDOFF.md 12번의 "세 작업 지점" 원칙을
실제로 실행 가능한 절차로 정리한 것이다.

## 시동어 한 쌍: "다비드" / "종료"

- **"다비드"** — 작업 시작 신호. 최신 상태를 읽어온다.
- **"종료"** — 작업 종료 신호. 이번 세션 내용을 문서에 저장한다.

### "다비드"라고 말했을 때 (세션 시작)
1. GitHub 저장소(`github.com/Dalbonz/David`, main 브랜치)에서 최신 상태를 가져온다.
   - Codespaces: `git pull`
   - 채팅(Cowork): 저장소가 Public이라 인증 없이 읽을 수 있다 — 아래 문서를 GitHub에서 직접 읽는다.
2. 아래 문서를 순서대로 읽고 현재 상태를 파악한다.
   - `docs/HANDOFF.md` — 지금 무엇이 구현돼 있고 무엇이 의도적으로 안 돼 있는지
   - `docs/PROGRESS.md` — 가장 최근 세션에서 무엇을 했는지 (맨 위 항목이 최신)
   - `docs/ROADMAP.md` — 장기 방향과 아직 정해지지 않은 것
3. 위 내용을 근거로 "지금 상태"를 짧게 요약해서 사용자에게 확인받은 뒤 작업을 시작한다.
   (추측으로 상태를 요약하지 않는다 — 문서를 실제로 읽은 뒤에만 요약한다.)

### "종료"라고 말했을 때 (세션 종료)
1. 이번 세션에서 한 일을 `docs/PROGRESS.md`에 HANDOFF.md 14번 형식으로 새 항목으로 추가한다
   (한 일 / 변경한 파일 / 확인 / 결정 또는 위험 / 다음 — 맨 위에 추가).
2. 문서 내용이 실제 코드 상태와 달라진 부분이 있으면 `docs/HANDOFF.md`, `docs/ROADMAP.md`도
   함께 갱신한다.
3. Codespaces 쪽은 commit → push까지 한다. 채팅(Cowork) 쪽은 변경한 파일을 사용자에게 전달해
   사용자가 반영하게 한다 (HANDOFF.md 12번 표 참고).
4. 저장/push가 끝났음을 사용자에게 확인시켜준다 ("종료"라고 말했는데 실제로 저장 안 된 채
   대화가 끝나면 다음 세션이 이어받을 근거가 없다 — 반드시 완료 여부를 확인해줄 것).

## 참고
- 이 절차는 HANDOFF.md 상단의 "AI 작업 규칙"(자체 검증 필수, 확인 안 된 내용은 "확인 필요"로
  명시)과 함께 적용된다.
- Codespaces/Claude Code 세션에서는 리포지토리 루트의 `CLAUDE.md`가 이 문서를 가리키도록
  연결해뒀다 — 매 세션 시작 시 자동으로 읽히므로, 여기서는 "다비드"라는 말 자체가 실제로
  작동한다.
- 채팅(Cowork) 세션은 `CLAUDE.md`를 자동으로 읽지 못한다. 아들이 대화를 시작할 때 "다비드,
  docs/PROCESS.md대로 시작해줘" 처럼 직접 언급해야 같은 절차가 적용된다. Cowork 쪽에 이 절차를
  자동으로 걸어둘 방법(프로젝트 지침 저장 기능 등)이 있는지는 **확인 필요** — 다음에 아들과
  함께 확인해볼 것.
- "다비드"는 이 절차의 시동어(세션 이어하기 신호)이며, 나중에 만들 DAVID 앱 자체의 음성
  웨이크워드(HANDOFF.md 4번)와는 별개의 개념이다. 이름은 같지만 하나는 "AI 세션을 여는 말",
  다른 하나는 "앱이 듣기 시작하는 말"이다.
