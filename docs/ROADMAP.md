# DAVID 프로젝트 로드맵

HANDOFF.md가 "지금 무엇이 구현돼 있는가"를 다룬다면, 이 문서는 "어디로 가는가"를 다룬다.
HANDOFF.md 2번(현재 파일 구조)에는 이 파일이 이미 있는 것처럼 적혀 있었지만, 2026-08-24 이전까지는
실제로 존재하지 않았다 — 이번에 처음 작성한다.

## 핵심 설계 원칙 (2026-08-24, 아들 아이디어 → 아버지가 세션 중 설명)

1. **모듈형 아키텍처**
   요청되는 모든 기능은 독립된 모듈로 만든다. 각 모듈은 언제든 붙이거나 뗄 수 있어야 하고,
   한 모듈을 고치거나 빼는 것이 다른 모듈에 영향을 주지 않아야 한다.
   → 모듈 경계를 실제로 어디서 나눌지(음성 인식/TTS/명령 해석/실행 등)는 **아직 미정**.

2. **음성 우선 입력**
   음성 명령이 기본 입력 방식이며, 아래 세 기기 모두에서 지원돼야 한다.
   - Galaxy Watch (워치)
   - Galaxy Buds (이어셋)
   - 휴대폰 (폰)
   모바일/PC에서의 타이핑 입력은 음성의 보조 수단으로 병행 지원한다.

3. **최종 완성 기준**
   영화 <아이언맨>의 자비스(J.A.R.V.I.S.) 같은 수준. 음성으로 **검색·지원·해결·수행**까지
   할 수 있어야 한다.

**중요**: 이 방향은 아들의 아이디어에서 시작됐고, 아버지 스스로도 "아직 구체화는 부족하다"고
밝혔다. 구체적인 모듈 목록·인터페이스 설계·우선순위는 정해지지 않았으며, 앞으로 아버지와 AI가
세션을 거듭하며 채워나가기로 했다. 이 문서의 1~3번 원칙 외의 내용(아래 포함)은 전부 추측이 아니라
"아직 결정 안 됨"으로 남겨둔다.

## 확정된 방향 (2026-08-31)

### 음성 입력: Bixby 커스텀 웨이크워드로 "다비드"를 앱 열기 트리거로만 쓴다
상시 웨이크워드 감지를 우리가 직접 만들지 않는다. 대신:
1. Bixby의 커스텀 웨이크워드 기능(설정 > 고급 기능 > Bixby > 음성 등록 > 기동어 만들기)에 "다비드"를 등록
2. Bixby 루틴으로 "다비드"를 들으면 DAVID 앱을 여는 액션만 연결
3. 앱이 열린 뒤부터는 전부 우리 코드 — 이미 `MainActivity.kt`에 있는 `SpeechRecognizer`가 실제
   질문을 받아 `Brain.reply()`로 넘긴다

상시 저전력 리스닝이라는 어려운 부분은 삼성(Bixby)에 맡기고, 실제 질문 인식과 답변 생성은 Bixby/
Gemini를 거치지 않고 전부 우리 Brain이 담당하는 구조.

### 두뇌: 우선 Claude
Bixby 내장 Gemini의 응답 품질이 부족하다는 판단(아버지)으로, `Brain` 구현체를 Claude로 만든다
(`ClaudeBrain`, 아직 미구현 — 지금은 `DemoBrain`만 있음). **Claude Pro 구독($20/월)과 앱이 쓸
Anthropic API는 별개 상품·별개 결제**임을 확인함 — Pro 구독은 API 사용량으로 넘어오지 않고, 앱에서
Claude를 호출하려면 API 키를 따로 발급받아 토큰 단위 종량제로 과금된다. 초기엔 사용량이 많고 점차
안정화될 것으로 예상하고 있음(아버지 판단, 실측 아님). 나중에 사용량이 커지면 HANDOFF.md 1번의
"무료/로컬 우선" 원칙에 따라 Ollama 등 로컬 대안으로 일부 옮길 가능성도 열어둔다.

**아직 검증 안 됨 (실기기 필요, 확인 필요)**:
- Bixby 커스텀 웨이크워드가 가족 실제 기기(HANDOFF.md 1번 — Fold 8 / S24+ / S24 FE / S24 Ultra,
  Watch4~8, Buds Pro 2~4)에서 실제로 지원되는지. 이 기능은 원래 Galaxy S25/One UI 7.0에서
  시작됐고 "다른 삼성 기기로도 최근 확대됐다"는 출처만 있어, 가족 4대(전부 S24 세대) 각각에서
  실제로 되는지는 확인 안 됨
- 워치의 Bixby에도 커스텀 웨이크워드가 똑같이 적용되는지, 버즈는 폰의 Bixby 라우팅을 그대로
  타는지
- 커스텀 웨이크워드가 "Hi Bixby"보다 인식 정확도가 떨어진다는 출처가 있어 실사용 체감 확인 필요
- Bixby 루틴이 "다비드"를 듣고 실제로 우리 앱을 안정적으로 열어주는지

## 아직 정해지지 않은 것 (확인 필요)

  음성/실행 쪽 경계는 미정)
- "검색·지원·해결·수행"을 실제 기능 단위로 어떻게 쪼갤지, `AgentAction`을 실제로 실행하는 코드
  (웹 검색 연동, 캘린더/알림 실행 등은 HANDOFF.md 4번에서 현재 "의도적으로 구현하지 않음"으로
  명시된 항목들과 겹침 — 이 로드맵이 그 결정을 바꾸는 것인지 아직 확인 안 됨)
